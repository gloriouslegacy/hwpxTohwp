# hwpx→hwp 변환 기능명세

## F1 한컴 COM 변환 엔진
조건: S1, Q1, Q2, C1, C4, C5, V1, D3
- 입력: hwpx 경로 1개, 출력 hwp 경로 1개. 출력: 성공 / 실패(이유).
- 한/글 2014에서 쓸 수 있는 COM API만 사용한다. 한/글 인스턴스는 STA 스레드 하나에서 한 번 만들어 다시 쓰고, 창은 숨긴다.
- 예외: 한/글이 설치되어 있지 않으면 변환을 시작하지 않고 안내한다. 열기 실패·암호 문서·저장 실패는 그 파일만 실패로 처리한다.
완료 기준: 한/글 2014가 설치된 Windows에서 샘플 hwpx 를 넣으면 한/글로 열리는 .hwp 가 만들어지고, 원본 hwpx 는 바이트 단위로 그대로다.
테스트: T1.1 정상 hwpx → hwp 생성(수동·Windows) / T1.2 암호 hwpx → 실패, 이유 "암호" / T1.3 한/글 미설치(ProgID 없음) → 시작 전 안내 / T1.4 엔진 인터페이스를 가짜 구현으로 바꿔 나머지 흐름이 돈다(자동)

## F2 입력 수집
조건: S1, S2
- 파일·폴더를 끌어다 놓거나 [추가] 버튼으로 넣는다. 폴더는 하위 폴더까지 `*.hwpx` 를 찾는다(확장자 대소문자 무시).
- 같은 파일이 두 번 들어오면 하나만 남긴다. 목록에서 항목을 빼거나 비울 수 있다.
완료 기준: 하위 폴더 2단계에 있는 hwpx 까지 목록에 나오고, hwpx 가 아닌 파일과 중복은 빠진다.
테스트: T2.1 중첩 폴더 수집 / T2.2 `.HWPX` 대문자 포함 / T2.3 같은 파일 두 번 → 1개 / T2.4 .hwp·.txt 제외

## F3 출력 경로 계산
조건: S3, D1
- 기본은 원본과 같은 폴더. 출력 폴더를 지정하면 그 폴더에 저장하고, 폴더 입력이었다면 그 폴더 기준 상대 경로를 그대로 만든다.
- 같은 이름 파일이 있으면 `이름_1.hwp`, `이름_2.hwp` … 로 정한다. 같은 실행 안에서 두 입력이 같은 출력 이름이 되어도 겹치지 않는다.
완료 기준: 기존 파일은 절대 덮어쓰지 않고, 출력 폴더를 지정하면 하위 구조가 그대로 만들어진다.
테스트: T3.1 기본(같은 폴더) / T3.2 출력 폴더 + 하위 구조 / T3.3 기존 a.hwp → a_1.hwp / T3.4 a.hwp·a_1.hwp 있음 → a_2.hwp / T3.5 같은 실행에서 이름 충돌

## F4 일괄 실행·진행·취소
조건: Q3, Q4
- 변환은 백그라운드에서 돌리고 파일별 상태(대기/진행/성공/실패)와 전체 진행률을 보여준다.
- [취소]를 누르면 지금 파일까지만 처리하고 멈춘다. 실패한 파일은 건너뛰고 계속한다.
완료 기준: 변환 중에도 창이 응답하고 취소할 수 있으며, 실패 파일이 섞여 있어도 나머지는 성공한다.
테스트: T4.1 가짜 엔진에서 3번째 파일 실패 → 나머지 성공(자동) / T4.2 취소 → 남은 파일은 대기 상태로 남음(자동) / T4.3 UI 응답성(수동·Windows)

## F5 결과 요약·로그
조건: S4
- 끝나면 성공·실패 개수와 실패 파일·이유를 보여준다.
- 로그는 `%LOCALAPPDATA%\hwpx2hwp\logs\yyyyMMdd-HHmmss.log` 에 남기고, 화면의 [로그 열기]로 연다.
완료 기준: 실패한 파일마다 경로와 이유가 로그에 한 줄씩 남는다.
테스트: T5.1 실패 2건 → 로그 2줄 + 요약 개수 일치(자동)

## F6 보안 모듈 등록
조건: D2
- exe 폴더에 한컴 보안 모듈 DLL이 있으면 레지스트리(현재 사용자 범위)에 등록하고 엔진 시작 때 모듈을 등록한다.
- 없거나 등록에 실패하면 "승인 팝업이 뜰 수 있음" 안내를 한 번 보여주고 계속한다.
완료 기준: DLL이 있으면 승인 팝업 없이 변환되고, 없으면 안내 뒤 변환이 계속된다.
테스트: T6.1 DLL 있음(수동·Windows) / T6.2 DLL 없음 → 안내 후 계속(자동, 가짜 엔진)
