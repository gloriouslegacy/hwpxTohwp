# hwpx→hwp 변환 요구사항

## 목적
Windows 사용자가 .hwpx 문서를 .hwp(HWP 5.0)로 한꺼번에 변환한다. 변환 품질은 한컴오피스에서 "다른 이름으로 저장"한 결과와 같아야 한다.

## 사용 시나리오
- S1 파일 몇 개를 창에 끌어다 놓고 [변환]을 누르면 같은 폴더에 .hwp 가 생긴다.
- S2 폴더를 끌어다 놓으면 하위 폴더까지 포함해 안의 .hwpx 를 모두 변환한다.
- S3 출력 폴더를 지정하면 결과를 그 폴더에 저장한다(폴더 일괄일 때는 원래 하위 폴더 구조를 그대로 만든다).
- S4 변환이 끝나면 파일별 성공·실패와 실패 이유를 화면에서 보고, 로그 파일로도 남긴다.

## 품질 속성
- Q1 변환 결과는 한컴 COM 저장 결과와 같다(직접 변환하지 않음).
- Q2 원본 .hwpx 는 절대 고치거나 지우지 않는다.
- Q3 변환 중에도 UI가 멈추지 않고 진행률을 보여주며 취소할 수 있다.
- Q4 파일 하나가 실패해도 나머지는 계속 변환한다.

## 제약
- C1 Windows 10/11 x64. 한/글 2014 이상이 설치되어 있어야 한다(사용자 PC에 설치된 버전이 2014). 한/글 2014에서 실제로 쓸 수 있는 COM API만 사용한다.
- C5 최신 한/글(2022 이상)에서 만든 hwpx 에 2014가 모르는 요소가 있으면 결과에서 빠질 수 있다. 이 손실은 한/글 2014 자체의 한계로 보고, 변환 실패로 처리하지 않는다.
- C2 C# .NET 10 (LTS) WinForms, self-contained 단일 exe 로 배포한다.
- C3 개발은 macOS에서 한다. 빌드만 여기서 하고, 실행·COM 테스트는 Windows PC에서 사용자가 한다.
- C4 COM 호출은 STA 스레드 하나에서 한/글 인스턴스 하나를 다시 써서 처리한다.

## 변경 축
- V1 변환 엔진이 늘어날 수 있다(한컴이 없는 환경을 위한 직접 변환). 엔진은 인터페이스 뒤로 숨긴다.
- V2 CLI 진입점이 추가될 수 있다. 변환 로직은 UI와 분리한다.
- V3 반대 방향(hwp→hwpx)이나 PDF 같은 다른 출력 형식이 추가될 수 있다.

## 결정된 세부 (2026-10-21 사용자 승인)
- D1 출력 위치에 같은 이름 파일이 있으면 `이름_1.hwp`, `이름_2.hwp` … 로 저장한다. 옵션 UI는 두지 않는다.
- D2 한/글 보안 모듈(FilePathCheckerModule DLL)이 exe 폴더에 있으면 자동으로 등록해서 쓴다. 없으면 승인 팝업이 뜰 수 있다고 안내하고 계속 진행한다. DLL은 사용자가 한컴 개발자 사이트에서 직접 받는다.
- D3 암호가 걸린 hwpx 는 실패로 처리하고 이유를 기록한다.
