# Windows 수동 테스트 체크리스트

한/글 2014 가 설치된 Windows PC 에서 직접 따라 한다. 근거: `docs/spec/convert.md` T1.1·T1.2·T1.3·T4.3·T6.1, `docs/design/baseline.md` D-9 와 open issues.

## 준비

- [ ] `dotnet publish` 로 만든 `hwpx2hwp.exe` 를 `C:\hwptest\app\` 에 둔다(경로는 짧고 공백 없이). 같은 폴더에 보안 모듈 DLL 도 둔다(T6.1 에서 쓴다).
- [ ] 샘플 문서를 `C:\hwptest\in\` 에 둔다.
  - 정상 hwpx: 본문·표·그림이 든 것 1개, 한 줄짜리 것 1개
  - 암호 hwpx: 한/글에서 문서 암호를 걸어 저장한 실제 파일 1개
  - 대량: 정상 hwpx 20개 이상(T4.3)
  - 깨진 hwpx: 정상 파일을 일부 잘라낸 것 1개(선택)
- [ ] 출력 폴더 `C:\hwptest\out\` 을 비워 둔다.
- [ ] 한/글 2014 가 열려 있지 않은지 확인한다(작업 관리자에서 Hwp.exe 없음).
- 기록: PC·Windows 버전 ______ / 한/글 2014 버전·패치 ______ / 날짜 ______

## Windows 에서 확인할 사실

| # | 확인할 사실 | 확인 방법 | 결과 |
|---|---|---|---|
| 1 | Hwp.exe 가 32비트인가 64비트인가 | 작업 관리자 > 세부 정보 > 열 추가 > 플랫폼(또는 `(32 비트)` 표시) | |
| 2 | 보안 모듈 DLL 의 파일 이름 | 한/글 설치 폴더·배포받은 보안 모듈 폴더에서 확인. 이름을 `docs/design/baseline.md` 상수 1곳과 비교 | |
| 3 | 보안 모듈 DLL 의 비트 수(Hwp.exe 와 같아야 함) | 탐색기 > 속성 또는 `dumpbin /headers` 의 machine 값 | |

| 7 | `SetMessageBoxMode` 지원 여부 | T1.1·T1.2 중 확인 대화상자가 뜨는지 | |
| 8 | 260자 넘는 경로에서 `SaveAs` 동작 | X1(아래)에서 확인 | |

## T1.1 정상 hwpx 를 hwp 로 변환

- [ ] 준비물: 정상 hwpx 2개, 보안 모듈 DLL 이 exe 폴더에 있는 상태
- 단계
  1. `hwpx2hwp.exe` 를 실행한다.
  2. 정상 hwpx 2개를 추가하고 출력 폴더를 `C:\hwptest\out\` 로 정한다.
  3. 변환을 시작한다.
  4. 끝나면 출력 폴더의 `.hwp` 를 한/글 2014 로 직접 연다.
- 기대 결과: 2개 모두 성공 표시. `.hwp` 가 생기고 한/글에서 열린다. 본문·표·그림이 원본과 같다. 변환 중 한/글 창이 보이지 않고, 끝나면 Hwp.exe 프로세스가 남지 않는다. 원본 hwpx 는 바뀌지 않는다.
- 결과: 성공 / 실패 ______ / 메모 ______________________

## T1.2 실제 암호 hwpx 는 실패하고 이유가 "암호"

- [ ] 준비물: 암호 hwpx 1개, 정상 hwpx 1개
- 단계
  1. 암호 hwpx 와 정상 hwpx 를 함께 추가해 변환을 시작한다.
  2. 암호 대화상자가 뜨는지 지켜본다(뜨면 사실 #5 에 기록).
  3. 끝난 뒤 목록의 결과와 이유를 확인한다.
- 기대 결과: 암호 파일은 실패이고 이유에 "암호" 가 보인다. 암호 입력 창이 뜨지 않는다. 정상 파일은 성공한다. 출력 폴더에 암호 파일의 `.hwp` 가 생기지 않는다.
- 결과: 성공 / 실패 ______ / 이유 문구 ______________________

## T1.3 한/글 미설치(ProgID 없음) 안내

- [ ] 준비물: 한/글 이 설치되지 않은 Windows(가상 머신 또는 다른 PC). 없으면 이 항목은 "미수행" 으로 기록
- 단계
  1. 한/글 이 없는 PC 에 `hwpx2hwp.exe` 를 복사해 실행한다.
  2. 정상 hwpx 를 추가하고 변환을 시작한다.
- 기대 결과: 변환 시작 전에 한/글 이 필요하다는 안내가 뜬다. 파일은 처리되지 않고 앱이 비정상 종료하지 않는다.
- 결과: 성공 / 실패 / 미수행 ______ / 메모 ______________________

## T4.3 UI 응답성

- [ ] 준비물: 대량 정상 hwpx 20개 이상
- 단계
  1. 20개 이상을 한 번에 추가하고 변환을 시작한다.
  2. 진행 중에 창을 이동·크기 조절하고 목록을 스크롤한다.
  3. 진행 중 취소를 누른다.
- 기대 결과: 창이 "응답 없음" 이 되지 않고 진행 표시가 갱신된다. 취소하면 남은 파일은 대기 상태로 남고, 진행 중이던 파일 이후 더 처리되지 않는다. 끝나면 Hwp.exe 가 남지 않는다.
- 결과: 성공 / 실패 ______ / 멈춘 시간(초) ______

## T6.1 보안 모듈 DLL 있음

- [ ] 준비물: 보안 모듈 DLL(사실 #2·#3 확인 후), 정상 hwpx 1개
- 단계
  1. `regedit` 로 `HKCU\Software\HNC\HwpAutomation\Modules` 를 확인해 현재 값을 적어 둔다.
  2. DLL 을 exe 폴더에 둔 채 변환을 실행한다.
  3. 다시 `regedit` 를 확인한다.
  4. 같은 변환을 한 번 더 실행한다.
- 기대 결과: 값 이름 `FilePathCheckerModule` 에 DLL 전체 경로가 들어 있다(그 키의 그 값 1개만 바뀜, HKLM 은 그대로). 파일 접근 허용 확인 창이 뜨지 않고 변환이 성공한다. 두 번째 실행에서 값이 그대로다.
- 결과: 성공 / 실패 ______ / 레지스트리 값 ______________________

## X1 (확인용, 명세 밖) 260자 넘는 경로

- [ ] 준비물: 출력 폴더 경로가 260자를 넘도록 만든 폴더, 정상 hwpx 1개
- 단계
  1. 중첩 폴더로 출력 경로를 260자 이상으로 만든다.
  2. 그 폴더를 출력 폴더로 정해 변환한다.
- 기대 결과: 성공하거나, 실패하면 저장 실패(`SaveFailed`)로 기록되고 앱은 계속 동작한다. 어느 쪽인지 사실 #8 에 적는다.
- 결과: 성공 / 저장 실패 / 기타 ______
